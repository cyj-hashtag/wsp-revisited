## 0. 先花 10 分钟看懂全局

**我们要证明什么**：MIT 那篇博客说，GPT-6 Astra 只改了 Qwen3.5-0.8B 0.016% 的权重，数学成绩就从 7.9% 涨到 48.1%。我们怀疑它主要做的是"让模型停得下来"，而不是"让模型更会做题"。

**三个研究问题**，各一句话：

- **RQ1**：换成 Qwen 官方推荐的解码设置，或者加一个"检测到循环就让它停下来作答"的简单办法，原模型能不能追上编辑后的模型？
- **RQ2**：不用任何 LLM，只用一个经典的自动流程（求"循环方向"再把它减掉），能不能找到同样有效的编辑？
- **RQ3**：用数学讲清楚这种编辑在做什么（命题 1–3）；再用生存分析把准确率拆成"能不能结束"和"结束后对不对"两部分。

**你在这个项目里有三个身份**：

1. **决策者**：判定标准、论文怎么讲、什么时候发布，都由你拍板。你是唯一作者。
2. **实验操作员**：租卡，在 GPU 机器上执行 Claude 给你的命令，盯着任务跑完。
3. **数学作者**：RQ3 的证明和生存分析由你主导，这是你最有优势、也最能体现你贡献的部分。

**两天的节奏**：

```
第 1 天：准备（3h） → 冒烟测试（2h） → 晚上让 RQ1 跑一整夜，你推命题
第 2 天：早上看 RQ1 定叙事 → 跑 RQ2 → 生存分析 → 写作 → 晚上发布
```

### 1.5 选一个租卡平台

平台不限：AutoDL 等国内平台、RunPod / Vast.ai / Lambda 等国外平台、学校的服务器都可以。脚本只要求 Linux + NVIDIA GPU，不依赖某一家。选的时候对照这几条：

- [ ] **GPU**：按 100 元预算（2026-11-04 定），租**同一台机器上的 2–4 张 RTX 3090**（首选，性价比最高）或 4090，脚本会按卡数自动分片。H 系列跑得快，但每个 token 贵十倍以上，会超预算。必须是 Ampere 或更新的架构（30/40/50 系、A10/A40/A100/A800、L20/L40、H 系列）。**V100、P100、T4 不行**：vLLM 0.33.0 用的是 CUDA 13 版的 PyTorch，CUDA 13 已不支持 V100 这类老架构；它们也没有模型要求的 bfloat16。
  - 参考价（比价站 gpuprice.dev，2026-11-03）：3090 晨涧云 ¥0.80/时、恒源云 ¥0.99、智星云 ¥1.10；4090 算家云 ¥1.24、晨涧云 ¥1.38。当时 AutoDL 无卡。以平台页面的价格和库存为准。
- [ ] **驱动（硬条件）**：`nvidia-smi` 右上角显示的 CUDA 版本必须 ≥ 13.0，也就是驱动版本 ≥ 580。vLLM 0.33.0 没有 CUDA 12 的版本（2026-11-04 查过）。开机后第一件事就是看这一行：
  - 不够时，如果是云服务器（虚拟机），Claude 可以升级驱动，约 20 分钟；
  - 如果是容器（和 AutoDL 一样，驱动由宿主机决定），只能换机器。
- [ ] **系统和镜像**：Ubuntu 22.04 / 24.04。镜像里自带的 CUDA 版本不重要（vLLM 自己带 CUDA 运行库），重要的是上一条的驱动；云服务器上选带 CUDA 的镜像，因为它装好了驱动。Ubuntu 22.04 自带的 Python 3.10 太旧（vLLM 0.33.0 要 ≥ 3.11），Claude 会另装 3.12。
- [ ] **硬盘**：数据盘 ≥ 80GB；系统盘够大（例如 200GB）就不用另加。
- [ ] **网络**：能访问 GitHub 最好；访问不了也没关系，Claude 会从你的电脑把代码和作者日志拷过去。访问不了 Hugging Face 也没关系，脚本会自动改用 hf-mirror。
- [ ] **计费**：按小时计费、能随时关机。最好有"不带 GPU 也能开机"的模式（AutoDL 叫"无卡模式"），装环境时几乎不花钱。
- [ ] **预算**：注册的 RQ1 全部实验约 2.6 亿 token，加上完整的 RQ2 约 4 亿（`results/cost_estimate.json`，用原作者公开的生成文本实测估算）。一张 3090 / 4090 每小时约跑 900 万 token，误差 ±50%，冒烟测试后用实测值重算。所以 RQ1 约 30 卡时，加 RQ2 约 45 卡时；按 ¥0.8–1.0 / 卡时，约 ¥25–45，吞吐量最差时也不超过 ¥80。**租卡和充值前先和 Claude 一起算好钱。**

## 5. 出问题时怎么办

| 情况 | 做法 |
|---|---|
| 冒烟测试数字对不上 | 停下来，把输出贴给 Claude。不要往下跑 |
| 实例掉线或被释放 | 结果是分片写在数据盘上的，重新开机后用同一条命令断点续跑 |
| vLLM 报错、不支持这个模型 | 让 Claude 对齐第三方复现用的版本（vLLM 0.33.0）。还不行就换卡型 |
| 结果和假设相反 | 照写，换用预注册里对应的结论模板 |
| 时间不够 | 按这个顺序砍：RQ4 → D4 → 缩小 RQ2 网格 → GSM8K 改用 500 题子集 |
| 和 Claude 意见不一致 | 你是作者，你拍板。但涉及"数字是否可靠"时，宁可多跑一次验证 |

## 附录 B：术语表（给数学系同学的版本）

| 术语 | 意思 |
|---|---|
| token | 模型读写文字的最小单位，大约是半个英文单词或一个汉字。"32k 上限"是指最多生成 32,768 个 token |
| thinking 模式 | 模型先在 `<think>…</think>` 里写草稿式推理，再给出答案。0.8B 默认关闭；原文把它打开了 |
| 循环 / 截断 | 模型在思考里不断重复同一段话、停不下来，直到撞上长度上限被截断，没有答案 |
| temperature | 采样温度。下一个 token 的概率先按 p^(1/T) 调整再归一化。T 越低越保守，小模型越容易重复 |
| top_p / top_k | 只在概率最高的一部分候选里采样：累计概率达到 p 的那些，或者前 k 个 |
| presence penalty | 对已经出现过的 token 统一扣分，用来抑制重复 |
| vLLM | 高效的大模型推理引擎，能同时生成成百上千条回答 |
| 残差流 | Transformer 每层都往同一个 1024 维向量上"加"东西。这个向量就是残差流，可以理解成模型的工作记忆 |
| MLP / down_proj | 每层的前馈网络：先升到 3584 维，过非线性，再用 down_proj（一个 1024×3584 的矩阵）降回 1024 维加进残差流。down_proj 的第 j 列就是第 j 个神经元往残差流"写"的向量 |
| 方向消融 / steering | 找一个代表某种行为的方向 u，把激活在 u 上的分量减掉（消融）或加上（steering）。原文的编辑就是这类操作 |
| teacher forcing | 把一段现成的文本喂给模型，只读它内部的激活，不让它自己生成 |
| MATH-500 / GSM8K / IFEval | 分别是竞赛数学 500 题、小学应用题 1319 题、指令遵循 541 题 |
| 配对 bootstrap | 对"题目"有放回地重抽样，在同一批题上算两个模型的准确率差，重复一万次得到置信区间 |
| Kaplan–Meier | 生存分析里估计 S(t) = P(T > t) 的方法，能正确处理"被截断、没观察到结束"的样本（右删失）。在每个结束时刻 t_i，Ŝ(t) 乘上 (1 − d_i/n_i)：d_i 是在 t_i 结束的条数，n_i 是到 t_i 时仍在"风险集"里的条数 |
| 预注册 | 实验前先把假设和判定标准写死并公开时间戳，防止事后挑结果 |

## 附录 C：常用命令

下面每一条都在 GPU 机器的终端里执行。

新建一个叫 `run` 的 tmux 会话，长任务都在里面跑：

```bash
tmux new -s run
```

在 tmux 里按 `Ctrl-b` 再按 `d` 退出，任务继续在后台跑。之后用这条命令回去看：

```bash
tmux attach -t run
```

查看 GPU 的显存和利用率：

```bash
nvidia-smi
```

实时查看日志（把路径换成 Claude 告诉你的那个），按 `Ctrl-c` 退出：

```bash
tail -f results/xxx/log.txt
```

查看磁盘剩余空间：

```bash
df -h
```

查看某个目录占了多少空间：

```bash
du -sh /root/autodl-tmp/*
```

把仓库同步到最新：

```bash
git pull
```
